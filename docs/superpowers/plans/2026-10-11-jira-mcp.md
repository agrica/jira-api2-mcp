# Jira MCP (Jira Server / Data Center, REST API v2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Révision 4 (2026-10-11).** Ce document remplace la révision 3. Les modifications, les informations retirées et les décisions restant à confirmer sont récapitulées à la fin, dans « Révision 4 — résumé des modifications ».

> **Valeurs d'exemple.** Toutes les valeurs propres à un environnement sont **fictives** : l'URL `https://jira.example.com` (domaine réservé à la documentation), le projet `DEMO`, l'utilisateur `jdoe`, les identifiants `customfield_100NN`, le secret `JIRA_READONLY_PAT`, les numéros de version et de build `8.20.0` / `820000`. Le code et la documentation ne contiennent aucune information propre à une organisation, une instance ou un réseau réels. Chaque utilisateur fournit ses propres valeurs par variables d'environnement, variables GitHub et secrets GitHub.

**Goal:** Un serveur MCP stdio en TypeScript, générique, pour une instance **Jira Software Server / Data Center 8.x** auto-hébergée. Il expose :
- les opérations **décrites dans les WADL publiés par l'instance cible** pour REST API v2 (`/rest/api/2`), Agile 1.0 (`/rest/agile/1.0`) et Xray Server/DC (`/rest/raven/1.0`) ;
- des outils typés pour les usages courants.

Le serveur est **en lecture seule par défaut**. Les écritures ne sont disponibles qu'après activation explicite.

**Architecture:** Un client HTTP unique, `JiraClient`. Il gère :
- l'authentification par PAT en Bearer ;
- HTTPS exigé par défaut, et les redirections refusées ;
- une garde d'écriture fondée sur la **classe d'accès** de l'opération ;
- des reprises réservées aux lectures ;
- une limite de taille appliquée pendant la lecture du corps ;
- l'**annulation** : un appel MCP annulé interrompt la requête Jira en cours.

Deux couches d'outils s'appuient sur ce client :
1. **Catalogue.** Il est produit à partir des WADL par un pipeline outillé. Chaque opération reçoit une classe d'accès (`read`, `write` ou `destructive`) :
   - une règle par défaut, fondée sur la méthode HTTP ;
   - des **décisions de revue** signées, consignées dans un fichier versionné ;
   - des heuristiques de chemin, qui **désignent** les opérations à revoir sans rien prouver.

   Le catalogue est un fichier JSON **chargé au démarrage**. Il n'est pas compilé dans le code, si bien que l'inventaire des endpoints n'entre pas dans le dépôt (voir « Données versionnées et CI »).

   Il est exposé par les outils `jira_list_operations`, `jira_describe_operation`, `jira_call_read_operation` et `jira_call_write_operation`, ce dernier seulement si les écritures sont activées.
2. **Outils dédiés.** Environ 25 outils curés, avec des schémas zod précis. Les outils d'écriture ne sont enregistrés que lorsque les écritures sont activées.

**Tech Stack:**

**Spec:** Il n'y a pas de spec formelle. Le plan s'appuie sur la demande du 2026-10-11, sur les corrections des révisions 2 à 4, et sur les caractéristiques génériques de Jira Server / Data Center décrites dans « Prérequis de l'instance cible ».

## Prérequis de l'instance cible

- **Produit.** Jira Software **Server ou Data Center 8.x**, qui expose REST API v2. Jira Cloud (API v3, ADF, `accountId`) est hors périmètre.
- **Authentification.** Par **Personal Access Token** (disponible à partir de Jira 8.14) : `Authorization: Bearer <PAT>`.
- **API v2.** Descriptions et commentaires en **wiki markup** (pas ADF). Utilisateurs identifiés par `name` (ex. fictif `jdoe`), pas par `accountId`.
- **WADL.** L'instance doit publier `application.wadl` pour chaque famille cataloguée. Le nombre d'opérations dépend de la version de Jira et des plugins installés ; il est mesuré par `catalog:build`, jamais supposé.
- **Xray.** Facultatif. La source Xray est marquée `optional: true` dans `scripts/lib/sources.ts` : un 404 est consigné dans `absent` (méta et verrou), et son apparition ou sa disparition est détectée comme une dérive (décision H16, révisée).
- **Erreurs.** Certaines erreurs, notamment les 404, renvoient une **page HTML** et non du JSON ; le client en extrait le titre.
- **Champs personnalisés.** Leurs identifiants (`customfield_NNNNN`) **varient d'une instance à l'autre**. Ils se découvrent avec `jira_list_fields` ; aucun identifiant n'est codé en dur.
- **Écrans et workflows.** Selon la configuration, `editmeta` peut être vide pour un utilisateur ; la modification passe alors par une transition dont les champs se lisent via `GET …/transitions?expand=transitions.fields`.
- **Réseau.** La machine qui exécute le serveur, et en CI le runner, doit pouvoir joindre l'instance en HTTPS. Une instance accessible seulement depuis un réseau privé exige un poste ou un runner situé dans ce réseau (voir « CI GitHub Actions »).
- **Certificats.** Si le certificat de l'instance est émis par une autorité de certification **privée**, celle-ci doit être reconnue par Node :
  - soit installée dans le magasin système, Node étant lancé avec `--use-system-ca` (les scripts npm le font ; l'option est sans effet nuisible avec une autorité publique) ;
  - soit fournie par `NODE_EXTRA_CA_CERTS=<chemin du fichier PEM>`.

  Ne jamais désactiver la vérification TLS (`NODE_TLS_REJECT_UNAUTHORIZED=0` est interdit).

## Portée réelle

**Couvert.** Les opérations décrites par les trois WADL listés dans `scripts/lib/sources.ts`, à la date du téléchargement. La version de Jira, la date et l'empreinte de chaque WADL sont enregistrées dans `catalog/source-lock.json`.

**Familles non couvertes.** Elles peuvent être présentes ou absentes selon l'instance et ses plugins ; dans tous les cas, elles ne sont pas cataloguées :

| Famille | Exemples de préfixes |
|---|---|
| Jira Service Management | `/rest/servicedeskapi` |
| Plugins tiers (suivi du temps, actifs, gestion de tests autres que Xray, scripts…) | préfixes propres à chaque plugin |
| API internes ou annexes de Jira | `/rest/greenhopper/1.0`, `/rest/auth/1`, `/rest/pat/latest`, `/rest/dev-status/1.0`, `/rest/plugins/1.0`, `/rest/applinks` |
| Alias de version | `/rest/api/latest` |

Une famille non cataloguée ne pourrait être ajoutée que si elle publie un WADL ; ce point dépend de l'instance.

**Limites propres aux WADL (générés par Jersey).**
- **Corps.** Seuls les *media types* acceptés sont décrits : aucun schéma, et rien qui indique si le corps est **requis**.
- **Paramètres de requête.** `required` est rarement déclaré, beaucoup de types sont `xs:string`, et des paramètres lus par programme peuvent manquer.
- **Effets de bord.** Le WADL ne dit **rien** des effets de bord d'une opération. Un GET qui écrit ne s'y distingue pas d'un GET de lecture.
- **Permissions.** Toutes les ressources y figurent, y compris celles d'administration, les ressources WebSudo et les ressources internes ou dépréciées.
- **Descriptions.** Les textes `doc` sont partiels.

**Conséquence.** La validation du serveur porte sur ce que le WADL déclare. Pour le reste, c'est Jira qui valide.

## Politique d'écriture et classification

1. **Lecture seule par défaut.** Les écritures exigent `JIRA_ALLOW_WRITES=true`.
2. **Classe d'accès.** Chaque opération porte `access` (`read`, `write` ou `destructive`) et un `accessReason` qui dit d'où vient la classe.
   - **Règle par défaut :**

     | Méthode | Classe | `accessReason` |
     |---|---|---|
     | GET, HEAD, OPTIONS | `read` | `default rule: safe HTTP method (not individually reviewed)` |
     | DELETE | `destructive` | `default rule: DELETE method` |
     | POST, PUT, PATCH | `write` | `default rule: unsafe HTTP method` |
   - **Décisions de revue.** Elles sont consignées dans `catalog/access-decisions.json`, qui est versionné. Chaque entrée contient :
     - `access` ;
     - `reason` ;
     - `reviewedBy`, l'identité git de la personne qui a relu ;
     - `reviewedOn`, la date de la revue.

     Une décision prime sur la règle par défaut. Son `accessReason` prend la forme `reviewed: <raison> (<relecteur>, <date>)`.

     Une décision `read` est interdite sur un DELETE. Les autres combinaisons sont permises : un GET peut être reclassé `write` ou `destructive`, un POST peut l'être en `read` ou en `destructive`.
3. **Candidats à la revue, désignés par des heuristiques de chemin.** `scripts/lib/classify.ts` (`REVIEW_HEURISTICS`) en distingue trois catégories :

   | Catégorie | Méthodes | Mots du chemin | Classes possibles |
   |---|---|---|---|
   | `get-side-effect` | GET, HEAD, OPTIONS | `reindex`, `run`, `execute`, `trigger`, `start`, `stop`, `clear`, `reset`, `purge`, `delete`, `remove`, `sync`, `refresh`, `generate`, `logout`, `lock`, `send`, `notify`, `import`, `enable`, `disable`… | `read`, `write`, `destructive` |
   | `post-read-like` | POST | `search`, `query`, `picker`, `find`, `export`, `validate`, `check`, `preview`, `count` | `read` ou `write` |
   | `write-destructive-like` | POST, PUT, PATCH | `delete`, `remove`, `purge`, `clear`, `reset`, `truncate`, `archive`, `bulk`, `merge`, `move`, `restore`, `rollback`, `revoke`, `disable`, `destroy`, `cleanup`, `reindex`… | `write` ou `destructive` |

   **Ces heuristiques ne détectent rien.** Elles ne reclassent jamais une opération. Elles sélectionnent seulement des opérations qu'une personne doit examiner : la documentation Atlassian ou Xray, et au besoin le comportement observé sur une instance de recette. Un mot du chemin n'est jamais une preuve, ni dans un sens ni dans l'autre.
4. **Vérification de la classification.**
   - **Candidats en attente.** `catalog:build` écrit `catalog/review.md` : les candidats par catégorie, ceux qui sont décidés et ceux qui restent en attente.
   - **Contrôle bloquant.** `catalog:check` **échoue** tant qu'il reste un candidat sans décision. Il échoue aussi si une décision vise une opération disparue, ou si elle est incomplète : raison, relecteur ou date manquant, relecteur laissé en gabarit.
   - **Verrou.** Le verrou `catalog/source-lock.json` contient l'empreinte des opérations classées. Une décision modifiée sans mise à jour du verrou fait donc échouer `catalog:check`.
   - **Relecture.** Toute modification de `catalog/access-decisions.json` passe par une revue de code par une **seconde personne**. → [H14]
   - **Dérive.** Lorsque Jira ou un plugin ajoute des opérations, les nouveaux candidats sont « en attente » et bloquent la livraison jusqu'à leur revue.
5. **Risque résiduel sur les GET (H11).**
   - **Ce qui est revu.** La revue obligatoire porte sur les candidats désignés par les heuristiques. Les autres GET restent `read` par la règle par défaut, avec la mention visible `not individually reviewed`. Leur nombre figure dans `catalog/review.md` et dans la note de livraison.
   - **Le risque.** Un GET à effet de bord dont le chemin ne contient aucun mot-clé ne serait **pas** signalé. Il serait alors appelable par `jira_call_read_operation`, y compris quand les écritures sont désactivées.
   - **Traitement retenu :**
     - revue obligatoire des candidats ;
     - marquage `not individually reviewed`, visible dans `jira_describe_operation` et `jira_list_operations` ;
     - recommandation d'utiliser un PAT dont les **permissions Jira** correspondent à l'usage. En lecture seule, ce peut être un compte de service sans droit d'écriture. Ce sont ces permissions, appliquées par Jira, qui constituent la barrière effective ;
     - **acceptation explicite** du risque, consignée dans la note de livraison (Task 12).
   - **Ce qui n'est pas fait.** Aucune revue exhaustive de tous les GET n'est réalisée par défaut. L'alternative est indiquée en H11.
6. **Application de la garde.**

   | Couche | Comportement |
   |---|---|
   | Client HTTP | Chaque requête déclare son `access`. Sans `allowWrites`, une requête `write` ou `destructive` est refusée avant tout appel réseau. |
   | Outils dédiés | Les outils d'écriture ne sont pas enregistrés quand les écritures sont désactivées. |
   | Outil générique | `jira_call_read_operation` refuse toute opération non `read`, quel que soit le verbe. `jira_call_write_operation` n'existe qu'avec les écritures activées, et il refuse les opérations `read`. |
7. **Annotations MCP.**
   - **Ce que sont les annotations.** Des **indications** destinées au client MCP, par exemple pour lui faire demander une confirmation. Ce n'est **pas** un mécanisme de sécurité : la garde réelle est appliquée par le serveur.

   | Outils | Annotations |
   |---|---|
   | Lecture | `readOnlyHint: true`, `idempotentHint: true` |
   | Écriture dédiée | `destructiveHint: false`, avec `idempotentHint` selon l'outil |
   | `jira_delete_issue` | `destructiveHint: true` |

   - **Choix conservateur (H13).** `jira_call_write_operation` est annoté `destructiveHint: true`, même lorsqu'il appelle une modification courante. Une même annotation couvre en effet tous ses appels, qui peuvent inclure des suppressions. Une opération classée `write` peut aussi se révéler destructive si la revue l'a manquée. Ce choix est dit dans la description de l'outil, testé et documenté dans le README.
8. **`jira_add_attachment`** reste conservé tel quel :
   - schéma `filePath` et envoi multipart vers Jira ;
   - aucune restriction de chemin, aucune liste blanche, aucune confirmation supplémentaire.

   Il est activé avec les autres écritures lorsque `JIRA_ALLOW_WRITES=true`.

## Politique de reprise HTTP

**Requêtes qui peuvent être réessayées.** Les requêtes de classe `read` dont le corps n'est pas multipart :
- GET, HEAD et OPTIONS ;
- les POST décidés `read`, comme la recherche JQL.

**Déclencheurs.** HTTP 429, 502, 503 et 504, les erreurs réseau et les timeouts.

**Paramètres.** Deux reprises au maximum. Le délai suit `Retry-After`, plafonné à 10 s, avec un repli exponentiel de 500 ms, puis 1 s.

**Écritures (`write` et `destructive`) : jamais réessayées automatiquement.** Cela vaut aussi pour les PUT et DELETE : dans Jira, l'idempotence dépend de l'endpoint. Un 429 sur une écriture est renvoyé avec la valeur de `Retry-After`. → [H4]

## Annulation

- **Principe.** Lorsqu'un client MCP annule un appel d'outil (`notifications/cancelled`), la requête HTTP Jira en cours est interrompue.
- **Source du signal.** Dans `@modelcontextprotocol/server` 2.3.1, le second argument d'un handler d'outil est un `ServerContext`. Son champ `ctx.mcpReq.signal` est un `AbortSignal`, documenté comme « used to communicate if the request was cancelled from the sender's side ».
  - Ce point a été **vérifié uniquement dans les fichiers de types** du paquet publié (`dist/*.d.mts`), le 2026-10-11. Il n'a pas été vérifié à l'exécution.
  - Le comportement réel est vérifié par le test de bout en bout de la Task 7. → [H15]
- **Propagation.**
  - `defineTool` exécute chaque handler dans un contexte `AsyncLocalStorage` (`src/http/cancellation.ts`) qui porte ce signal.
  - `JiraClient.request` le combine avec le timeout (`AbortSignal.any`). Les outils n'ont donc pas à transmettre le signal eux-mêmes, et aucun outil ne peut l'oublier.
  - Une requête peut aussi recevoir un `signal` explicite.
- **Effets.**
  - Un signal déjà annulé empêche tout appel réseau.
  - Une annulation pendant l'appel, ou pendant l'attente qui précède une reprise, lève `RequestCancelledError`, **sans nouvelle tentative**.
  - Le message d'erreur distingue l'annulation du timeout.
- **Limite pour les écritures.** Interrompre une requête côté client n'annule pas un traitement que Jira a déjà reçu. Pour une écriture, le message d'erreur indique que l'opération **a pu être appliquée**, et qu'il faut vérifier son état avant de la relancer.
- **Si le SDK ne propage pas l'annulation à l'exécution**, c'est-à-dire si le test de bout en bout échoue alors que le test du client passe :
  1. ne pas contourner le problème par un mécanisme maison ;
  2. consigner la limite dans le README : « l'annulation MCP n'interrompt pas la requête Jira ; elle reste bornée par `JIRA_TIMEOUT_MS` » ;
  3. marquer ce seul test `it.fails`, avec un commentaire qui renvoie à H15 ;
  4. signaler l'écart au responsable du plan.

  La prise en charge du signal par le client HTTP reste en place, et testée.

## Transport

- **HTTPS exigé par défaut.** `JIRA_BASE_URL` doit être en `https://`.
- **Exception.** Une URL `http://` n'est acceptée qu'avec `JIRA_ALLOW_INSECURE_HTTP=true`, pour des tests locaux exceptionnels. Dans ce cas, le serveur affiche au démarrage un avertissement sur stderr : le PAT circule en clair. → [H6]
- **Redirections.** Elles sont refusées (`redirect: 'error'`). → [H8]

## Données versionnées et CI

L'inventaire des endpoints de l'instance est considéré comme une information interne. Il apparaît dans les WADL, dans le catalogue généré, dans le rapport de différences, dans le rapport de revue et dans l'artefact de CI.

**Mode par défaut retenu (B) : cet inventaire n'est jamais publié dans le dépôt.** L'URL de l'instance n'est versionnée nulle part : elle vient de `JIRA_BASE_URL`.

| Fichier | Contenu | Versionné (mode B) |
|---|---|---|
| `catalog/source-lock.json` | Version et build de Jira, date de téléchargement, chemins relatifs des WADL, sha256 et taille de chaque WADL, comptes par famille, empreinte des opérations, résumé chiffré du dernier changement. **Aucune URL d'instance.** | **oui** |
| `catalog/access-decisions.json` | Décisions de revue : identifiants des seules opérations revues, classe, raison, relecteur, date | **oui** (voir H7b) |
| `catalog/wadl/*.wadl`, `catalog/wadl/fetch-meta.json` | WADL bruts, qui contiennent l'URL de l'instance, et métadonnées du téléchargement | non (`.gitignore`) |
| `catalog/catalog.json` | Catalogue complet, chargé par le serveur au démarrage | non (`.gitignore`) |
| `catalog/last-diff.md`, `catalog/review.md` | Différences d'opérations, rapport de revue | non (`.gitignore`) |
| `dist/`, `*.tgz` | Build et paquet | non (`.gitignore`) |

**Comment les fichiers non versionnés sont produits**

- **Poste de développement.** `npm run catalog:fetch` (PAT, lecture seule), puis `npm run catalog:build`.
- **CI GitHub Actions** (`.github/workflows/ci.yml`, Task 12) :
  1. Le job `static` tourne sur un runner GitHub-hosted, sans secret ni accès à Jira. Il exécute `npm ci`, puis `npm run check`.
  2. Le job `catalog-and-package` récupère les WADL avec le PAT d'un **compte Jira aux permissions minimales** (lecture seule).
     - Le PAT est lu depuis un **secret GitHub** configuré par l'utilisateur. Le nom donné en exemple est `JIRA_READONLY_PAT`.
     - Il n'est transmis **qu'aux étapes qui appellent Jira** ou qui recherchent sa valeur.
  3. Ce même job génère le catalogue, exécute `catalog:check`, construit le serveur et lance le test de fumée en lecture seule. Il crée ensuite le paquet `npm pack`, qui contient `dist/` et `catalog/catalog.json`.
  4. Le paquet est contrôlé : contenu attendu, absence du PAT. Il est ensuite conservé comme **artefact du workflow** (`actions/upload-artifact`), avec une durée de rétention limitée. Rien n'est commité.
  5. Le répertoire de travail est nettoyé en fin de job. C'est surtout utile sur un runner self-hosted. → [H12]
- **Runner.**
  - Un runner GitHub-hosted ne convient que si l'instance est joignable depuis Internet, avec un certificat émis par une autorité publique.
  - Sinon, il faut un **runner self-hosted**, placé dans un réseau qui atteint l'instance et qui fait confiance à son autorité. C'est le cas si l'instance est sur un réseau privé, ou si son autorité de certification privée ne peut pas être installée sur un runner éphémère.
  - Le label du runner est une variable du dépôt (`JIRA_RUNNER_LABEL`), pas une valeur codée en dur.
- **Visibilité de l'artefact.** Un artefact est téléchargeable par toute personne qui a accès en lecture au dépôt.
  - L'artefact n'est donc publié que si la variable `PUBLISH_ARTIFACT` vaut `true`.
  - Cette variable ne doit être activée que sur un **dépôt privé ou interne**. → [H12]
- **Journaux.**
  - GitHub masque la valeur des secrets dans les journaux.
  - En plus, les scripts n'affichent jamais le PAT.
  - Lorsque `CI=true`, ils n'impriment que des **comptes** pour les différences et la revue, jamais la liste des endpoints.
- **Installation.** Deux possibilités, décrites dans le README :
  - récupérer l'artefact du workflow, qui contient le paquet et donc le catalogue ;
  - construire depuis les sources, avec un PAT.
- **Traçabilité des différences.** Le détail des opérations ajoutées, supprimées ou modifiées (`catalog/last-diff.md`) reste local. Le dépôt n'en conserve que le **résumé chiffré**, dans `catalog/source-lock.json` (`lastChange`).
- **Mode A (si H7 est confirmée positivement).** On retire de `.gitignore` les lignes `catalog/wadl/`, `catalog/catalog.json`, `catalog/last-diff.md` et `catalog/review.md`. Les scripts restent identiques. Attention : les WADL contiennent l'URL de l'instance.

`src/config.ts` :
```ts
import { z } from 'zod';

export interface JiraConfig {
  baseUrl: string;
  pat: string;
  allowWrites: boolean;
  allowInsecureHttp: boolean;
  timeoutMs: number;
  maxResponseBytes: number;
  maxOutputChars: number;
  catalogPath: string | undefined;
}

const flag = z.enum(['true', 'false', '1', '0']).transform((v) => v === 'true' || v === '1');

const envSchema = z.object({
  JIRA_BASE_URL: z.url({ protocol: /^https?$/ }).transform((url) => url.replace(/\/+$/, '')),
  JIRA_PAT: z.string().min(1),
  JIRA_ALLOW_WRITES: flag.default(false),
  JIRA_ALLOW_INSECURE_HTTP: flag.default(false),
  JIRA_TIMEOUT_MS: z.coerce.number().int().positive().default(30_000),
  JIRA_MAX_RESPONSE_BYTES: z.coerce.number().int().positive().default(5 * 1024 * 1024),
  JIRA_MAX_OUTPUT_CHARS: z.coerce.number().int().positive().default(100_000),
  JIRA_CATALOG_PATH: z.string().min(1).optional(),
});

export function loadConfig(env: Readonly<Record<string, string | undefined>>): JiraConfig {
  const result = envSchema.safeParse(env);
  if (!result.success) {
    const issues = result.error.issues.map((i) => `${i.path.join('.')}: ${i.message}`).join('; ');
    throw new Error(`Invalid configuration — ${issues}`);
  }
  const e = result.data;
  if (e.JIRA_BASE_URL.startsWith('http:') && !e.JIRA_ALLOW_INSECURE_HTTP) {
    throw new Error(
      'Invalid configuration — JIRA_BASE_URL: HTTPS is required by default because the PAT is sent with every request. ' +
        'Plain HTTP is accepted only with JIRA_ALLOW_INSECURE_HTTP=true, for exceptional local tests.',
    );
  }
  return {
    baseUrl: e.JIRA_BASE_URL,
    pat: e.JIRA_PAT,
    allowWrites: e.JIRA_ALLOW_WRITES,
    allowInsecureHttp: e.JIRA_ALLOW_INSECURE_HTTP,
    timeoutMs: e.JIRA_TIMEOUT_MS,
    maxResponseBytes: e.JIRA_MAX_RESPONSE_BYTES,
    maxOutputChars: e.JIRA_MAX_OUTPUT_CHARS,
    catalogPath: e.JIRA_CATALOG_PATH,
  };
}

export function startupWarnings(config: JiraConfig): string[] {
  return config.baseUrl.startsWith('http:')
    ? ['Plain HTTP enabled by JIRA_ALLOW_INSECURE_HTTP=true: the PAT travels unencrypted. Reserved for exceptional local tests.']
    : [];
}
```

  ```ts
  export interface JiraClientOptions { baseUrl: string; pat: string; allowWrites: boolean; timeoutMs: number; maxResponseBytes: number; fetch?: FetchLike; maxRetries?: number; sleep?: (ms: number) => Promise<void> }
  export class JiraClient { readonly allowWrites: boolean; request(req: JiraRequest): Promise<JiraResponse>; buildUrl(path: string, query?: Readonly<Record<string, QueryValue>>): URL }
  export function isRetryable(req: JiraRequest): boolean
  export function retryDelayMs(retryAfter: string | null, attempt: number): number
  ```

  Règles appliquées par `request` :
  - **Chemin.** Il doit commencer par `/rest/`.
  - **Cohérence.** `access: 'read'` est interdit avec DELETE.
  - **Garde d'écriture.** Sans `allowWrites`, une requête `write` ou `destructive` lève `WritesDisabledError` avant tout appel réseau.
  - **Redirections.** `redirect: 'error'`.
  - **Taille.** Rejet anticipé si `Content-Length` dépasse la limite. Sinon le flux est lu jusqu'à `maxResponseBytes`, puis interrompu par `ResponseTooLargeError`. Les corps d'erreur sont tronqués à 64 KiB.
  - **Reprises.** Seulement si `isRetryable(req)`, sur 429, 502, 503, 504, erreur réseau ou timeout, avec 2 reprises au maximum.
  - **Annulation.** Le signal effectif est `req.signal`, à défaut celui du contexte courant (`currentCancellationSignal()`, posé par `defineTool` en Task 7). Déjà annulé : `RequestCancelledError` sans appel réseau. Annulé pendant `fetch`, pendant la lecture du corps ou pendant l'attente d'une reprise : `RequestCancelledError`, sans nouvelle tentative. Le signal transmis à `fetch` est `AbortSignal.any([timeout, signal])`.

```ts
export class JiraApiError extends Error {
  readonly status: number;
  readonly details: string[];
  readonly retryAfter: string | null;

  constructor(status: number, method: string, path: string, details: string[], retryAfter: string | null = null) {
    const suffix = details.length > 0 ? `: ${details.join(' | ')}` : '';
    const rate = status === 429 ? ` — rate limited${retryAfter ? ` (Retry-After: ${retryAfter} s)` : ''}` : '';
    super(`Jira ${method} ${path} failed with HTTP ${status}${suffix}${rate}`);
    this.name = 'JiraApiError';
    this.status = status;
    this.details = details;
    this.retryAfter = retryAfter;
  }
}

export class WritesDisabledError extends Error {
  constructor(method: string, path: string) {
    super(
      `Writes are disabled: ${method} ${path} is classified as a write. Start the server with JIRA_ALLOW_WRITES=true to allow it.`,
    );
    this.name = 'WritesDisabledError';
  }
}

export class ResponseTooLargeError extends Error {
  readonly maxBytes: number;

  constructor(method: string, path: string, maxBytes: number) {
    super(
      `Jira ${method} ${path} response exceeds ${maxBytes} bytes (JIRA_MAX_RESPONSE_BYTES). Narrow the request (fields, maxResults, filters).`,
    );
    this.name = 'ResponseTooLargeError';
    this.maxBytes = maxBytes;
  }
}

export class RequestCancelledError extends Error {
  constructor(method: string, path: string, access: 'read' | 'write' | 'destructive') {
    const warning =
      access === 'read'
        ? ''
        : '. The operation may already have been applied by Jira: check its state before retrying.';
    super(`Jira ${method} ${path} cancelled by the MCP client${warning}`);
    this.name = 'RequestCancelledError';
  }
}

interface JiraErrorBody {
  errorMessages?: unknown;
  errors?: unknown;
  message?: unknown;
}

function detailsFromJson(body: string): string[] {
  try {
    const parsed = JSON.parse(body) as unknown;
    if (parsed === null || typeof parsed !== 'object') return [];
    const p = parsed as JiraErrorBody;
    const out: string[] = [];
    if (Array.isArray(p.errorMessages)) out.push(...p.errorMessages.map(String));
    if (p.errors !== null && typeof p.errors === 'object') {
      for (const [field, message] of Object.entries(p.errors)) out.push(`${field}: ${String(message)}`);
    }
    if (typeof p.message === 'string') out.push(p.message);
    return out;
  } catch {
    return [];
  }
}

export function extractErrorDetails(body: string, contentType: string | null): string[] {
  if (contentType?.includes('json')) {
    const fromJson = detailsFromJson(body);
    if (fromJson.length > 0) return fromJson;
  }
  const title = /<title>([^<]*)<\/title>/i.exec(body)?.[1]?.trim();
  if (title) return [title];
  const text = body.trim();
  return text ? [text.slice(0, 500)] : [];
}
```

```ts
import { setTimeout as delay } from 'node:timers/promises';
import { currentCancellationSignal } from './cancellation.ts';
import {
  JiraApiError,
  RequestCancelledError,
  ResponseTooLargeError,
  WritesDisabledError,
  extractErrorDetails,
} from './jira-error.ts';

export type HttpMethod = 'GET' | 'POST' | 'PUT' | 'DELETE' | 'PATCH' | 'HEAD' | 'OPTIONS';
export type Access = 'read' | 'write' | 'destructive';
export type QueryScalar = string | number | boolean;
export type QueryValue = QueryScalar | readonly QueryScalar[] | undefined;
export type FetchLike = (input: string | URL, init?: RequestInit) => Promise<Response>;

export interface JiraRequest {
  method: HttpMethod;
  /** Absolute REST path, e.g. `/rest/api/2/issue/DEMO-1`. */
  path: string;
  /** Access class of the operation: drives the write guard and the retry policy. */
  access: Access;
  query?: Readonly<Record<string, QueryValue>>;
  /** Serialised as JSON, unless it is a `FormData` (multipart upload). */
  body?: unknown;
  accept?: string;
  /** Cancels the request. Defaults to the cancellation signal of the current MCP call, if any. */
  signal?: AbortSignal;
}

export interface JiraResponse {
  status: number;
  data: unknown;
}

export interface JiraClientOptions {
  baseUrl: string;
  pat: string;
  allowWrites: boolean;
  timeoutMs: number;
  maxResponseBytes: number;
  fetch?: FetchLike;
  maxRetries?: number;
  /** Waits before a retry; should reject or return early when `signal` aborts. */
  sleep?: (ms: number, signal?: AbortSignal) => Promise<void>;
}

const RETRYABLE_STATUS: ReadonlySet<number> = new Set([429, 502, 503, 504]);
const ERROR_BODY_MAX_BYTES = 64 * 1024;
const MAX_RETRY_DELAY_MS = 10_000;

export function isRetryable(req: JiraRequest): boolean {
  return req.access === 'read' && !(req.body instanceof FormData);
}

export function retryDelayMs(retryAfter: string | null, attempt: number): number {
  const seconds = retryAfter === null ? Number.NaN : Number(retryAfter);
  const delay = Number.isFinite(seconds) && seconds >= 0 ? seconds * 1000 : 500 * 2 ** attempt;
  return Math.min(delay, MAX_RETRY_DELAY_MS);
}

function parseBody(text: string, contentType: string | null): unknown {
  if (text === '') return null;
  if (contentType?.includes('json')) return JSON.parse(text) as unknown;
  return text;
}

async function readBody(
  res: Response,
  maxBytes: number,
  onOverflow: 'throw' | 'truncate',
  req: JiraRequest,
  signal: AbortSignal | undefined,
): Promise<string> {
  const declared = Number(res.headers.get('content-length') ?? Number.NaN);
  if (onOverflow === 'throw' && Number.isFinite(declared) && declared > maxBytes) {
    await res.body?.cancel();
    throw new ResponseTooLargeError(req.method, req.path, maxBytes);
  }
  if (!res.body) return '';
  const reader = res.body.getReader();
  const chunks: Uint8Array[] = [];
  let total = 0;
  for (;;) {
    if (signal?.aborted) {
      await reader.cancel();
      throw new RequestCancelledError(req.method, req.path, req.access);
    }
    const { done, value } = await reader.read();
    if (done) break;
    total += value.byteLength;
    if (total > maxBytes) {
      await reader.cancel();
      if (onOverflow === 'throw') throw new ResponseTooLargeError(req.method, req.path, maxBytes);
      chunks.push(value.subarray(0, value.byteLength - (total - maxBytes)));
      break;
    }
    chunks.push(value);
  }
  return new TextDecoder().decode(Buffer.concat(chunks));
}

export class JiraClient {
  readonly allowWrites: boolean;
  readonly #baseUrl: string;
  readonly #pat: string;
  readonly #timeoutMs: number;
  readonly #maxResponseBytes: number;
  readonly #fetch: FetchLike;
  readonly #maxRetries: number;
  readonly #sleep: (ms: number, signal?: AbortSignal) => Promise<void>;

  constructor(options: JiraClientOptions) {
    this.allowWrites = options.allowWrites;
    this.#baseUrl = options.baseUrl.replace(/\/+$/, '');
    this.#pat = options.pat;
    this.#timeoutMs = options.timeoutMs;
    this.#maxResponseBytes = options.maxResponseBytes;
    this.#fetch = options.fetch ?? globalThis.fetch;
    this.#maxRetries = options.maxRetries ?? 2;
    this.#sleep = options.sleep ?? ((ms, signal) => delay(ms, undefined, { signal }));
  }

  async request(req: JiraRequest): Promise<JiraResponse> {
    if (!req.path.startsWith('/rest/')) {
      throw new Error(`Refusing to call a non-REST path: ${req.path}`);
    }
    if (req.access === 'read' && req.method === 'DELETE') {
      throw new Error(`Inconsistent request: DELETE ${req.path} cannot be classified as read`);
    }
    if (!this.allowWrites && req.access !== 'read') {
      throw new WritesDisabledError(req.method, req.path);
    }
    const cancel = req.signal ?? currentCancellationSignal();
    if (cancel?.aborted) throw new RequestCancelledError(req.method, req.path, req.access);
    const url = this.buildUrl(req.path, req.query);
    const { headers, body } = this.#prepare(req);
    const retryable = isRetryable(req);

    for (let attempt = 0; ; attempt++) {
      const canRetry = retryable && attempt < this.#maxRetries;
      let res: Response;
      try {
        res = await this.#send(url, { method: req.method, headers, body, redirect: 'error' }, req, cancel);
      } catch (error) {
        if (!canRetry || error instanceof RequestCancelledError) throw error;
        await this.#pause(retryDelayMs(null, attempt), req, cancel);
        continue;
      }
      if (canRetry && RETRYABLE_STATUS.has(res.status)) {
        await res.body?.cancel();
        await this.#pause(retryDelayMs(res.headers.get('retry-after'), attempt), req, cancel);
        continue;
      }
      const contentType = res.headers.get('content-type');
      if (!res.ok) {
        const text = await readBody(res, ERROR_BODY_MAX_BYTES, 'truncate', req, cancel);
        throw new JiraApiError(
          res.status,
          req.method,
          req.path,
          extractErrorDetails(text, contentType),
          res.headers.get('retry-after'),
        );
      }
      const text = await readBody(res, this.#maxResponseBytes, 'throw', req, cancel);
      return { status: res.status, data: parseBody(text, contentType) };
    }
  }

  buildUrl(path: string, query?: Readonly<Record<string, QueryValue>>): URL {
    const url = new URL(this.#baseUrl + path);
    for (const [key, value] of Object.entries(query ?? {})) {
      if (value === undefined) continue;
      const values: readonly QueryScalar[] = typeof value === 'object' ? value : [value];
      for (const v of values) url.searchParams.append(key, String(v));
    }
    return url;
  }

  #prepare(req: JiraRequest): { headers: Record<string, string>; body: RequestInit['body'] } {
    const headers: Record<string, string> = {
      Authorization: `Bearer ${this.#pat}`,
      Accept: req.accept ?? 'application/json',
    };
    if (req.body === undefined) return { headers, body: undefined };
    if (req.body instanceof FormData) {
      headers['X-Atlassian-Token'] = 'no-check';
      return { headers, body: req.body };
    }
    headers['Content-Type'] = 'application/json';
    return { headers, body: JSON.stringify(req.body) };
  }

  async #pause(ms: number, req: JiraRequest, cancel: AbortSignal | undefined): Promise<void> {
    try {
      await this.#sleep(ms, cancel);
    } catch (error) {
      if (!cancel?.aborted) throw error;
    }
    if (cancel?.aborted) throw new RequestCancelledError(req.method, req.path, req.access);
  }

  async #send(url: URL, init: RequestInit, req: JiraRequest, cancel: AbortSignal | undefined): Promise<Response> {
    const timeout = AbortSignal.timeout(this.#timeoutMs);
    const signal = cancel ? AbortSignal.any([timeout, cancel]) : timeout;
    try {
      return await this.#fetch(url, { ...init, signal });
    } catch (error) {
      if (cancel?.aborted) throw new RequestCancelledError(req.method, req.path, req.access);
      if (timeout.aborted || (error instanceof DOMException && error.name === 'TimeoutError')) {
        throw new Error(`Jira ${req.method} ${req.path} timed out after ${this.#timeoutMs} ms`, { cause: error });
      }
      const message = error instanceof Error ? error.message : String(error);
      const cause = error instanceof Error && error.cause instanceof Error ? ` (${error.cause.message})` : '';
      throw new Error(`Jira ${req.method} ${req.path} failed: ${message}${cause}`, { cause: error });
    }
  }
}
```

```ts
import { XMLParser } from 'fast-xml-parser';
import type { HttpMethod } from '../../src/http/jira-client.ts';
import type { ApiFamily, OperationParam, ParamType, ParsedOperation } from '../../src/catalog/types.ts';

type XmlDoc = string | { '#text'?: string };
interface XmlParam {
  name: string;
  style?: string;
  type?: string;
  required?: string;
  repeating?: string;
  default?: string;
  doc?: XmlDoc[];
}
interface XmlRequest {
  param?: XmlParam[];
  representation?: { mediaType?: string }[];
}
interface XmlMethod {
  name: string;
  doc?: XmlDoc[];
  request?: XmlRequest[];
}
interface XmlResource {
  path: string;
  param?: XmlParam[];
  method?: XmlMethod[];
  resource?: XmlResource[];
}
interface XmlRoot {
  application?: { resources?: { base: string; resource?: XmlResource[] }[] };
}

const ARRAY_TAGS = new Set(['resources', 'resource', 'method', 'param', 'request', 'representation', 'doc']);
const METHODS: ReadonlySet<string> = new Set<HttpMethod>(['GET', 'POST', 'PUT', 'DELETE', 'PATCH', 'HEAD', 'OPTIONS']);

const parser = new XMLParser({
  ignoreAttributes: false,
  attributeNamePrefix: '',
  removeNSPrefix: true,
  textNodeName: '#text',
  stopNodes: ['*.doc'],
  isArray: (name, _jpath, _isLeaf, isAttribute) => !isAttribute && ARRAY_TAGS.has(name),
});

function mapType(xsType: string | undefined): ParamType {
  const t = (xsType ?? 'string').replace(/^xs:/, '');
  if (['int', 'long', 'short', 'integer', 'byte'].includes(t)) return 'integer';
  if (['double', 'float', 'decimal'].includes(t)) return 'number';
  if (t === 'boolean') return 'boolean';
  return 'string';
}

function decodeEntities(text: string): string {
  return text
    .replace(/&lt;/g, '<')
    .replace(/&gt;/g, '>')
    .replace(/&quot;/g, '"')
    .replace(/&#39;|&apos;/g, "'")
    .replace(/&#(\d+);/g, (_m, code: string) => String.fromCodePoint(Number(code)))
    .replace(/&amp;/g, '&');
}

function docText(docs: XmlDoc[] | undefined): string {
  const raw = (docs ?? []).map((d) => (typeof d === 'string' ? d : (d['#text'] ?? ''))).join(' ');
  return decodeEntities(raw).replace(/<[^>]+>/g, ' ').replace(/\s+/g, ' ').trim().slice(0, 400);
}

function joinPath(base: string, segment: string): string {
  const clean = segment.replace(/\{\s*(\w+)\s*:[^}]*\}/g, '{$1}').replace(/^\/+|\/+$/g, '');
  return clean ? `${base}/${clean}` : base;
}

function toQueryParam(p: XmlParam): OperationParam {
  const description = docText(p.doc);
  return {
    name: p.name,
    in: 'query',
    type: mapType(p.type),
    required: p.required === 'true',
    repeating: p.repeating === 'true',
    ...(p.default === undefined ? {} : { default: p.default }),
    ...(description ? { description } : {}),
  };
}

function pathParams(path: string, templateTypes: ReadonlyMap<string, ParamType>): OperationParam[] {
  return [...path.matchAll(/\{(\w+)\}/g)].map((m) => {
    const name = m[1] ?? '';
    return { name, in: 'path' as const, type: templateTypes.get(name) ?? 'string', required: true, repeating: false };
  });
}

function walk(
  res: XmlResource,
  parentPath: string,
  parentTemplates: ReadonlyMap<string, ParamType>,
  api: ApiFamily,
  out: ParsedOperation[],
): void {
  const path = joinPath(parentPath, res.path);
  const templates = new Map(parentTemplates);
  for (const p of res.param ?? []) if (p.style === 'template') templates.set(p.name, mapType(p.type));
  const resourceQuery = (res.param ?? []).filter((p) => p.style === 'query').map(toQueryParam);

  for (const m of res.method ?? []) {
    if (!METHODS.has(m.name)) continue;
    const request = m.request?.[0];
    const query = [...resourceQuery, ...(request?.param ?? []).filter((p) => p.style === 'query').map(toQueryParam)];
    const unique = query.filter((p, i) => query.findIndex((q) => q.name === p.name) === i);
    const mediaTypes = [
      ...new Set((request?.representation ?? []).map((r) => r.mediaType).filter((t): t is string => Boolean(t))),
    ];
    out.push({
      id: `${m.name} ${path}`,
      api,
      method: m.name as HttpMethod,
      path,
      summary: docText(m.doc),
      body: { accepted: (request?.representation?.length ?? 0) > 0, mediaTypes },
      params: [...pathParams(path, templates), ...unique],
    });
  }
  for (const child of res.resource ?? []) walk(child, path, templates, api, out);
}

export function parseWadl(xml: string, api: ApiFamily): ParsedOperation[] {
  const root = parser.parse(xml) as XmlRoot;
  const out: ParsedOperation[] = [];
  for (const resources of root.application?.resources ?? []) {
    const base = new URL(resources.base).pathname.replace(/\/+$/, '');
    for (const res of resources.resource ?? []) walk(res, base, new Map(), api, out);
  }
  const seen = new Set<string>();
  return out
    .filter((op) => (seen.has(op.id) ? false : (seen.add(op.id), true)))
    .sort((a, b) => (a.id < b.id ? -1 : a.id > b.id ? 1 : 0));
}
```

```ts
import type { Access } from '../../src/http/jira-client.ts';
import type { AccessDecision, AccessDecisions, Operation, ParsedOperation } from '../../src/catalog/types.ts';

export type ReviewCategory = 'get-side-effect' | 'post-read-like' | 'write-destructive-like';

export interface ReviewCandidate {
  id: string;
  category: ReviewCategory;
  /** The path fragment that triggered the heuristic (a hint, never a proof). */
  matched: string;
}

const SAFE_METHODS: ReadonlySet<string> = new Set(['GET', 'HEAD', 'OPTIONS']);

/**
 * Path heuristics that select operations for HUMAN review. They detect nothing and never reclassify:
 * an operation without a matching word is not proven safe, and a matching word proves nothing.
 */
export const REVIEW_HEURISTICS: readonly { category: ReviewCategory; methods: ReadonlySet<string>; pattern: RegExp }[] = [
  {
    category: 'get-side-effect',
    methods: SAFE_METHODS,
    pattern:
      /(reindex|run|execute|trigger|start|stop|restart|cancel|abort|clear|reset|purge|delete|remove|rebuild|sync|refresh|generate|logout|lock|unlock|approve|reject|send|notify|import|upgrade|migrate|enable|disable|activate|deactivate)/i,
  },
  {
    category: 'post-read-like',
    methods: new Set(['POST']),
    pattern: /(search|query|picker|find|export|validate|check|preview|count)/i,
  },
  {
    category: 'write-destructive-like',
    methods: new Set(['POST', 'PUT', 'PATCH']),
    pattern:
      /(delete|remove|purge|clear|reset|truncate|archive|bulk|mass|merge|move|restore|rollback|revoke|disable|deactivate|destroy|drop|cleanup|wipe|reindex)/i,
  },
];

function defaultAccess(op: ParsedOperation): { access: Access; accessReason: string } {
  if (SAFE_METHODS.has(op.method)) {
    return { access: 'read', accessReason: 'default rule: safe HTTP method (not individually reviewed)' };
  }
  if (op.method === 'DELETE') return { access: 'destructive', accessReason: 'default rule: DELETE method' };
  return { access: 'write', accessReason: 'default rule: unsafe HTTP method' };
}

function validateDecision(op: ParsedOperation, d: AccessDecision): void {
  if (!d.reason.trim()) throw new Error(`Access decision for ${op.id}: "reason" is required`);
  if (!d.reviewedBy.trim() || d.reviewedBy.trim().startsWith('<')) {
    throw new Error(`Access decision for ${op.id}: "reviewedBy" must name the reviewer (git identity)`);
  }
  if (!/^\d{4}-\d{2}-\d{2}$/.test(d.reviewedOn)) {
    throw new Error(`Access decision for ${op.id}: "reviewedOn" must be a YYYY-MM-DD date`);
  }
  if (op.method === 'DELETE' && d.access === 'read') {
    throw new Error(`${op.id}: DELETE operations cannot be classified as read`);
  }
}

export function classifyOperations(
  parsed: readonly ParsedOperation[],
  decisions: AccessDecisions,
): { operations: Operation[]; staleDecisions: string[]; candidates: ReviewCandidate[]; pending: ReviewCandidate[] } {
  const ids = new Set(parsed.map((op) => op.id));
  const candidates: ReviewCandidate[] = [];
  const operations = parsed.map((op): Operation => {
    for (const h of REVIEW_HEURISTICS) {
      const match = h.methods.has(op.method) ? h.pattern.exec(op.path) : null;
      if (match) candidates.push({ id: op.id, category: h.category, matched: match[0] });
    }
    const d = decisions[op.id];
    if (!d) return { ...op, ...defaultAccess(op) };
    validateDecision(op, d);
    return {
      ...op,
      access: d.access,
      accessReason: `reviewed: ${d.reason.trim()} (${d.reviewedBy.trim()}, ${d.reviewedOn})`,
    };
  });
  return {
    operations,
    staleDecisions: Object.keys(decisions).filter((id) => !ids.has(id)).sort(),
    candidates,
    pending: candidates.filter((c) => !decisions[c.id]),
  };
}
```

```ts
import type { Operation } from '../../src/catalog/types.ts';

export interface CatalogDiff {
  added: string[];
  removed: string[];
  changed: string[];
}

export function diffOperations(before: readonly Operation[], after: readonly Operation[]): CatalogDiff {
  const b = new Map(before.map((op) => [op.id, JSON.stringify(op)]));
  const a = new Map(after.map((op) => [op.id, JSON.stringify(op)]));
  return {
    added: [...a.keys()].filter((id) => !b.has(id)).sort(),
    removed: [...b.keys()].filter((id) => !a.has(id)).sort(),
    changed: [...a.keys()].filter((id) => b.has(id) && b.get(id) !== a.get(id)).sort(),
  };
}

export function hasDrift(diff: CatalogDiff): boolean {
  return diff.added.length + diff.removed.length + diff.changed.length > 0;
}

export function summarizeDiff(diff: CatalogDiff, title: string): string {
  return `${title}: +${diff.added.length} −${diff.removed.length} ~${diff.changed.length}`;
}

export function describeDiff(
  diff: CatalogDiff,
  title: string,
  env: Readonly<Record<string, string | undefined>> = process.env,
): string {
  return env.CI === 'true' ? summarizeDiff(diff, title) : formatDiff(diff, title);
}

export function formatDiff(diff: CatalogDiff, title: string): string {
  const section = (label: string, ids: string[]) =>
    [`### ${label} (${ids.length})`, ...ids.map((id) => `- \`${id}\``), ''].join('\n');
  return [
    `## ${title}`,
    '',
    hasDrift(diff) ? '' : 'Aucune différence d’opérations.\n',
    section('Ajoutées', diff.added),
    section('Supprimées', diff.removed),
    section('Modifiées', diff.changed),
  ].join('\n');
}
```

```ts
export const CATALOG_DIR = new URL('../../catalog/', import.meta.url);
export const WADL_DIR = new URL('wadl/', CATALOG_DIR); //                  not versioned (mode B)
export const FETCH_META = new URL('wadl/fetch-meta.json', CATALOG_DIR); // not versioned (mode B)
export const SOURCE_LOCK = new URL('source-lock.json', CATALOG_DIR); //    versioned
export const DECISIONS = new URL('access-decisions.json', CATALOG_DIR); // versioned
export const CATALOG_JSON = new URL('catalog.json', CATALOG_DIR); //       not versioned (mode B)
export const LAST_DIFF = new URL('last-diff.md', CATALOG_DIR); //          not versioned (mode B)
export const REVIEW_REPORT = new URL('review.md', CATALOG_DIR); //         not versioned (mode B)

export const WADL_SOURCES: readonly { api: ApiFamily; path: string; file: string }[] = [
  { api: 'api', path: '/rest/api/2/application.wadl', file: 'api.wadl' },
  { api: 'agile', path: '/rest/agile/1.0/application.wadl', file: 'agile.wadl' },
  { api: 'xray', path: '/rest/raven/1.0/application.wadl', file: 'xray.wadl' },
];

export interface SourceFile {
  api: ApiFamily;
  path: string;
  file: string;
  sha256: string;
  bytes: number;
}

/** Deliberately carries no instance URL: the lock built from it is versioned. */
export interface FetchMeta {
  jiraVersion: string;
  jiraBuildNumber: number;
  fetchedAt: string;
  sources: SourceFile[];
}

export interface SourceLock extends FetchMeta {
  counts: Record<ApiFamily, number>;
  operationsSha256: string;
  lastChange: {
    fromVersion: string | null;
    toVersion: string;
    added: number;
    removed: number;
    changed: number;
    recordedAt: string;
  };
}

interface ServerInfo {
  version: string;
  buildNumber: number;
}

export async function fetchSources(client: JiraClient): Promise<{ meta: FetchMeta; xml: Map<string, string> }> {
  const info = (await client.request({ method: 'GET', path: '/rest/api/2/serverInfo', access: 'read' })).data as ServerInfo;
  const xml = new Map<string, string>();
  const sources: SourceFile[] = [];
  for (const source of WADL_SOURCES) {
    const { data } = await client.request({ method: 'GET', path: source.path, access: 'read', accept: 'application/xml' });
    if (typeof data !== 'string') throw new Error(`Unexpected WADL payload for ${source.path}`);
    xml.set(source.file, data);
    sources.push({ ...source, sha256: sha256(data), bytes: Buffer.byteLength(data) });
  }
  return {
    meta: {
      jiraVersion: info.version,
      jiraBuildNumber: info.buildNumber,
      fetchedAt: new Date().toISOString(),
      sources,
    },
    xml,
  };
}
```

`scripts/lib/build.ts` :
```ts
import { createHash } from 'node:crypto';
import type { AccessDecisions, ApiFamily, CatalogFile, Operation, ParsedOperation } from '../../src/catalog/types.ts';
import { classifyOperations, type ReviewCandidate, type ReviewCategory } from './classify.ts';
import type { CatalogDiff } from './diff.ts';
import type { FetchMeta, SourceLock } from './sources.ts';
import { parseWadl } from './wadl.ts';

export function sha256(text: string): string {
  return createHash('sha256').update(text, 'utf8').digest('hex');
}

export function operationsDigest(operations: readonly Operation[]): string {
  return sha256(JSON.stringify(operations));
}

export function verifyFiles(meta: FetchMeta, xml: ReadonlyMap<string, string>): void {
  for (const s of meta.sources) {
    const text = xml.get(s.file);
    if (text === undefined) throw new Error(`Missing WADL file catalog/wadl/${s.file} — run npm run catalog:fetch`);
    if (sha256(text) !== s.sha256) {
      throw new Error(`catalog/wadl/${s.file} does not match the sha256 recorded in catalog/wadl/fetch-meta.json`);
    }
  }
}

export function buildCatalog(input: {
  xml: ReadonlyMap<string, string>;
  decisions: AccessDecisions;
  meta: FetchMeta;
  generatedAt: string;
}): { catalog: CatalogFile; staleDecisions: string[]; candidates: ReviewCandidate[]; pending: ReviewCandidate[] } {
  const parsed: ParsedOperation[] = [];
  const counts: Record<ApiFamily, number> = { api: 0, agile: 0, xray: 0 };
  for (const s of input.meta.sources) {
    const text = input.xml.get(s.file);
    if (text === undefined) throw new Error(`Missing WADL file catalog/wadl/${s.file} — run npm run catalog:fetch`);
    const ops = parseWadl(text, s.api);
    counts[s.api] += ops.length;
    parsed.push(...ops);
  }
  const { operations, staleDecisions, candidates, pending } = classifyOperations(parsed, input.decisions);
  return {
    catalog: {
      meta: {
        jiraVersion: input.meta.jiraVersion,
        jiraBuildNumber: input.meta.jiraBuildNumber,
        fetchedAt: input.meta.fetchedAt,
        generatedAt: input.generatedAt,
        counts,
      },
      operations,
    },
    staleDecisions,
    candidates,
    pending,
  };
}

export function compareWithLock(meta: FetchMeta, catalog: CatalogFile, lock: SourceLock): string[] {
  const problems: string[] = [];
  if (meta.jiraVersion !== lock.jiraVersion || meta.jiraBuildNumber !== lock.jiraBuildNumber) {
    problems.push(
      `Jira version/build differs from catalog/source-lock.json: ${meta.jiraVersion} (${meta.jiraBuildNumber}) vs ${lock.jiraVersion} (${lock.jiraBuildNumber})`,
    );
  }
  for (const s of meta.sources) {
    if (lock.sources.find((l) => l.file === s.file)?.sha256 !== s.sha256) {
      problems.push(`WADL ${s.file} differs from catalog/source-lock.json (sha256)`);
    }
  }
  const { counts } = catalog.meta;
  if (counts.api !== lock.counts.api || counts.agile !== lock.counts.agile || counts.xray !== lock.counts.xray) {
    problems.push(`Operation counts differ from catalog/source-lock.json: ${JSON.stringify(counts)} vs ${JSON.stringify(lock.counts)}`);
  } else if (operationsDigest(catalog.operations) !== lock.operationsSha256) {
    problems.push(
      'Classified operations differ from catalog/source-lock.json (operationsSha256): run npm run catalog:build -- --update-lock after review',
    );
  }
  return problems;
}

export function makeLock(
  meta: FetchMeta,
  catalog: CatalogFile,
  previous: SourceLock | undefined,
  diff: CatalogDiff,
  recordedAt: string,
): SourceLock {
  return {
    ...meta,
    counts: catalog.meta.counts,
    operationsSha256: operationsDigest(catalog.operations),
    lastChange: {
      fromVersion: previous?.jiraVersion ?? null,
      toVersion: meta.jiraVersion,
      added: diff.added.length,
      removed: diff.removed.length,
      changed: diff.changed.length,
      recordedAt,
    },
  };
}

const CATEGORY_HELP: Record<ReviewCategory, string> = {
  'get-side-effect': 'GET dont le chemin évoque un effet de bord : décider read / write / destructive',
  'post-read-like': 'POST dont le chemin évoque une lecture : décider read / write',
  'write-destructive-like': 'POST/PUT/PATCH dont le chemin évoque une suppression ou un fort impact : décider write / destructive',
};

export function formatReview(
  catalog: CatalogFile,
  candidates: readonly ReviewCandidate[],
  pending: readonly ReviewCandidate[],
): string {
  const pendingKeys = new Set(pending.map((c) => `${c.category} ${c.id}`));
  const unreviewedGets = catalog.operations.filter(
    (o) => o.method === 'GET' && o.accessReason.includes('not individually reviewed'),
  ).length;
  const lines = [
    `# Revue des classifications — Jira ${catalog.meta.jiraVersion} (WADL ${catalog.meta.fetchedAt})`,
    '',
    'Heuristiques de chemin : elles désignent des opérations à revoir, elles ne prouvent rien.',
    '',
    `Candidats : ${candidates.length} — En attente : ${pending.length}`,
    `GET non revus individuellement : ${unreviewedGets} (risque résiduel H11)`,
    '',
  ];
  for (const category of Object.keys(CATEGORY_HELP) as ReviewCategory[]) {
    lines.push(`### ${category}`, '', CATEGORY_HELP[category], '');
    for (const c of candidates.filter((x) => x.category === category)) {
      const done = !pendingKeys.has(`${c.category} ${c.id}`);
      lines.push(`- [${done ? 'x' : ' '}] \`${c.id}\` (matched "${c.matched}")`);
    }
    lines.push('');
  }
  return lines.join('\n');
}
```

```ts
const PATTERNS: readonly { name: string; regex: RegExp }[] = [
  { name: 'Authorization header', regex: /authorization["']?\s*[:=]\s*["']?(?:bearer|basic)\s+[A-Za-z0-9+/=._-]{16,}/i },
  { name: 'Bearer token', regex: /\bbearer\s+[A-Za-z0-9+/=._-]{20,}/i },
  { name: 'JIRA_PAT assignment', regex: /JIRA_PAT["']?\s*[:=]\s*["']?(?!\$\{)[^\s"'$<.)]{8,}/ },
  { name: 'password assignment', regex: /\b(?:password|passwd|pwd)["']?\s*[:=]\s*["'][^"'$<]{4,}["']/i },
];

/** Returns the names of the secret patterns found in `text` (empty when clean). */
export function findSecrets(text: string, literals: readonly string[] = []): string[] {
  const found = PATTERNS.filter((p) => p.regex.test(text)).map((p) => p.name);
  if (literals.some((value) => value.trim().length >= 8 && text.includes(value.trim()))) {
    found.push('known secret value');
  }
  return found;
}
```

```ts
import { readFile, writeFile } from 'node:fs/promises';
import type { AccessDecisions, CatalogFile } from '../src/catalog/types.ts';
import { buildCatalog, formatReview, makeLock, verifyFiles } from './lib/build.ts';
import { diffOperations, formatDiff, hasDrift } from './lib/diff.ts';
import {
  CATALOG_JSON,
  DECISIONS,
  FETCH_META,
  LAST_DIFF,
  REVIEW_REPORT,
  SOURCE_LOCK,
  WADL_DIR,
  type FetchMeta,
  type SourceLock,
} from './lib/sources.ts';

const updateLock = process.argv.includes('--update-lock');
const readJson = async <T>(url: URL): Promise<T> => JSON.parse(await readFile(url, 'utf8')) as T;

const meta = await readJson<FetchMeta>(FETCH_META);
const decisions = await readJson<AccessDecisions>(DECISIONS);
const xml = new Map<string, string>();
for (const s of meta.sources) xml.set(s.file, await readFile(new URL(s.file, WADL_DIR), 'utf8'));
verifyFiles(meta, xml);

const previous = await readJson<CatalogFile>(CATALOG_JSON).catch(() => undefined);

  decisions,
  meta,
  generatedAt: new Date().toISOString(),
});
if (staleDecisions.length > 0) {
  throw new Error(`Stale entries in catalog/access-decisions.json: ${staleDecisions.join(', ')}`);
}
const diff = diffOperations(previous?.operations ?? [], catalog.operations);
if (previous && !hasDrift(diff) && previous.meta.fetchedAt === catalog.meta.fetchedAt) {
  catalog.meta.generatedAt = previous.meta.generatedAt; // unchanged content keeps its generation date
}

await writeFile(CATALOG_JSON, `${JSON.stringify(catalog, null, 2)}\n`, 'utf8');
await writeFile(
  LAST_DIFF,
  formatDiff(diff, `Jira ${previous?.meta.jiraVersion ?? '—'} → Jira ${catalog.meta.jiraVersion} (${catalog.meta.fetchedAt})`),
  'utf8',
);
await writeFile(REVIEW_REPORT, formatReview(catalog, candidates, pending), 'utf8');

const { counts } = catalog.meta;
console.error(`✔ ${catalog.operations.length} operations (api ${counts.api}, agile ${counts.agile}, xray ${counts.xray})`);

console.error(`  review: ${candidates.length} candidate(s), ${pending.length} pending (catalog/review.md)`);

if (updateLock) {
  if (pending.length > 0) {
    throw new Error(`Cannot update catalog/source-lock.json: ${pending.length} review candidate(s) pending`);
  }
  const previousLock = await readJson<SourceLock>(SOURCE_LOCK).catch(() => undefined);
  const lock = makeLock(meta, catalog, previousLock, diff, new Date().toISOString());
  await writeFile(SOURCE_LOCK, `${JSON.stringify(lock, null, 2)}\n`, 'utf8');
```

```ts
import type { Access, HttpMethod, JiraRequest, QueryScalar, QueryValue } from '../http/jira-client.ts';
import { normalizeForSearch } from '../util/normalize.ts';
import type { ApiFamily, CatalogMeta, Operation, OperationParam } from './types.ts';

export interface SearchOptions {
  query?: string;
  api?: ApiFamily;
  method?: HttpMethod;
  access?: Access;
  limit?: number;
}

export interface CallArguments {
  pathParams?: Readonly<Record<string, string | number>>;
  query?: Readonly<Record<string, QueryValue>>;
  body?: unknown;
}

export class CatalogError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'CatalogError';
  }
}

function checkType(op: Operation, p: OperationParam, value: QueryScalar): void {
  const text = String(value).trim();
  const ok =
    p.type === 'integer'
      ? /^-?\d+$/.test(text)
      : p.type === 'number'
        ? text !== '' && Number.isFinite(Number(text))
        : p.type === 'boolean'
          ? text === 'true' || text === 'false'
          : true;
  if (!ok) throw new CatalogError(`Parameter "${p.name}" of ${op.id} expects ${p.type}, got ${JSON.stringify(value)}`);
}

function encodePathParam(op: Operation, p: OperationParam, value: string | number | undefined): string {
  if (value === undefined) throw new CatalogError(`Missing path parameter "${p.name}" for ${op.id}`);
  const text = String(value);
  if (text === '' || text === '.' || text === '..') {
    throw new CatalogError(`Invalid value for path parameter "${p.name}": "${text}"`);
  }
  checkType(op, p, value);
  return encodeURIComponent(text);
}

export function describeOperation(op: Operation): Operation & { notes: string[] } {
  return {
    ...op,
    notes: [
      op.body.accepted
        ? `Accepts a request body (${op.body.mediaTypes.join(', ') || 'media type not declared'}). The WADL does not say whether the body is required and gives no schema: Jira validates its content.`
        : 'Takes no request body.',
      'Path and query parameters are checked against the WADL (declared names, types, repeatable, required when declared). The WADL may omit parameters or required flags; Jira performs the remaining checks.',
      `Access class: ${op.access} (${op.accessReason}).`,
    ],
  };
}

export class Catalog {
  readonly meta: CatalogMeta | undefined;
  readonly #operations: readonly Operation[];
  readonly #byId: ReadonlyMap<string, Operation>;
  readonly #haystacks: ReadonlyMap<string, string>;

  constructor(operations: readonly Operation[], meta?: CatalogMeta) {
    this.meta = meta;
    this.#operations = operations;
    this.#byId = new Map(operations.map((op) => [op.id, op]));
    this.#haystacks = new Map(operations.map((op) => [op.id, normalizeForSearch(`${op.id} ${op.summary}`)]));
  }

  get size(): number {
    return this.#operations.length;
  }

  get(id: string): Operation | undefined {
    return this.#byId.get(id.trim());
  }

  require(id: string): Operation {
    const op = this.get(id);
    if (!op) throw new CatalogError(`Unknown operation "${id}". Use jira_list_operations to find a valid operationId.`);
    return op;
  }

  search(options: SearchOptions = {}): { total: number; operations: Operation[] } {
    const terms = normalizeForSearch(options.query ?? '').split(/\s+/).filter(Boolean);
    const limit = Math.min(Math.max(options.limit ?? 20, 1), 100);
    const matches = this.#operations.filter(
      (op) =>
        (!options.api || op.api === options.api) &&
        (!options.method || op.method === options.method) &&
        (!options.access || op.access === options.access) &&
        terms.every((term) => this.#haystacks.get(op.id)?.includes(term)),
    );
    matches.sort((a, b) => a.path.length - b.path.length || (a.id < b.id ? -1 : a.id > b.id ? 1 : 0));
    return { total: matches.length, operations: matches.slice(0, limit) };
  }

  buildRequest(op: Operation, args: CallArguments = {}): JiraRequest {
    const pathParams = args.pathParams ?? {};
    const declaredPath = op.params.filter((p) => p.in === 'path');
    const unknownPath = Object.keys(pathParams).filter((k) => !declaredPath.some((p) => p.name === k));
    if (unknownPath.length > 0) {
      throw new CatalogError(
        `Unknown path parameter(s) for ${op.id}: ${unknownPath.join(', ')}. Expected: ${declaredPath.map((p) => p.name).join(', ') || 'none'}`,
      );
    }
    const path = op.path.replace(/\{(\w+)\}/g, (_match, name: string) => {
      const param: OperationParam = declaredPath.find((p) => p.name === name) ?? {
        name,
        in: 'path',
        type: 'string',
        required: true,
        repeating: false,
      };
      return encodePathParam(op, param, pathParams[name]);
    });

    const query = args.query ?? {};
    const declaredQuery = op.params.filter((p) => p.in === 'query');
    const unknownQuery = Object.keys(query).filter((k) => !declaredQuery.some((p) => p.name === k));
    if (unknownQuery.length > 0) {
      throw new CatalogError(
        `Unknown query parameter(s) for ${op.id}: ${unknownQuery.join(', ')}. Allowed: ${declaredQuery.map((p) => p.name).join(', ') || 'none'}`,
      );
    }
    for (const p of declaredQuery) {
      const value = query[p.name];
      if (value === undefined) continue;
      if (typeof value === 'object' && !p.repeating) {
        throw new CatalogError(
          `Parameter "${p.name}" of ${op.id} is not repeatable: pass a single value (Jira often expects a comma-separated list).`,
        );
      }
      for (const v of typeof value === 'object' ? value : [value]) checkType(op, p, v);
    }
    const missing = declaredQuery.filter((p) => p.required && query[p.name] === undefined).map((p) => p.name);
    if (missing.length > 0) {
      throw new CatalogError(`Missing required query parameter(s) for ${op.id}: ${missing.join(', ')}`);
    }

    if (args.body !== undefined) {
      if (!op.body.accepted) throw new CatalogError(`${op.id} does not accept a request body`);
      const types = op.body.mediaTypes;
      if (types.length > 0 && !types.some((t) => t.includes('json'))) {
        throw new CatalogError(
          `${op.id} expects ${types.join(', ')}, which the generic tool cannot send. Use a dedicated tool (e.g. jira_add_attachment).`,
        );
      }
    }
    return { method: op.method, path, access: op.access, query, body: args.body };
  }
}
```

```ts
import { readFile } from 'node:fs/promises';
import { fileURLToPath } from 'node:url';
import { z } from 'zod';
import type { CatalogFile } from './types.ts';

/** `src/catalog/load.ts` and `dist/catalog/load.js` both resolve to `<root>/catalog/catalog.json`. */
export const DEFAULT_CATALOG_PATH = fileURLToPath(new URL('../../catalog/catalog.json', import.meta.url));

const paramSchema = z.object({
  name: z.string().min(1),
  in: z.enum(['path', 'query']),
  type: z.enum(['string', 'integer', 'number', 'boolean']),
  required: z.boolean(),
  repeating: z.boolean(),
  default: z.string().optional(),
  description: z.string().optional(),
});

const operationSchema = z.object({
  id: z.string().min(1),
  api: z.enum(['api', 'agile', 'xray']),
  method: z.enum(['GET', 'POST', 'PUT', 'DELETE', 'PATCH', 'HEAD', 'OPTIONS']),
  path: z.string().startsWith('/rest/'),
  summary: z.string(),
  body: z.object({ accepted: z.boolean(), mediaTypes: z.array(z.string()) }),
  params: z.array(paramSchema),
  access: z.enum(['read', 'write', 'destructive']),
  accessReason: z.string().min(1),
});

const catalogSchema = z.object({
  meta: z.object({
    jiraVersion: z.string().min(1),
    jiraBuildNumber: z.number().int(),
    fetchedAt: z.string().min(1),
    generatedAt: z.string().min(1),
    counts: z.object({ api: z.number().int(), agile: z.number().int(), xray: z.number().int() }),
  }),
  operations: z.array(operationSchema),
});

export async function loadCatalogFile(path: string = DEFAULT_CATALOG_PATH): Promise<CatalogFile> {
  let text: string;
  try {
    text = await readFile(path, 'utf8');
  } catch (error) {
    if ((error as NodeJS.ErrnoException).code === 'ENOENT') {
      throw new Error(
        `Operation catalog not found at ${path}. It is not stored in git: run "npm run catalog:fetch" then "npm run catalog:build", or install a packaged build (README › Installation).`,
      );
    }
    throw error;
  }
  let json: unknown;
  try {
    json = JSON.parse(text);
  } catch {
    throw new Error(`Operation catalog at ${path} is not valid JSON`);
  }
  const result = catalogSchema.safeParse(json);
  if (!result.success) {
    const issues = result.error.issues.slice(0, 3).map((i) => `${i.path.join('.')}: ${i.message}`).join('; ');
    throw new Error(`Operation catalog at ${path} is invalid: ${issues}`);
  }
  return result.data;
}
```

```ts
  .describe('Project key, e.g. DEMO');

export function maxResultsSchema(defaultValue: number) {
  return z.number().int().min(1).max(100).default(defaultValue).describe('Page size (1-100)');

 * MCP annotations are HINTS for clients (e.g. to ask the user for confirmation).
 * They are not a security mechanism: the server enforces the write policy itself (see JiraClient).
 */
export const READ: ToolAnnotations = { readOnlyHint: true, idempotentHint: true, openWorldHint: true };
export const WRITE: ToolAnnotations = { readOnlyHint: false, destructiveHint: false, idempotentHint: false, openWorldHint: true };
export const WRITE_IDEMPOTENT: ToolAnnotations = { readOnlyHint: false, destructiveHint: false, idempotentHint: true, openWorldHint: true };
export const DESTRUCTIVE: ToolAnnotations = { readOnlyHint: false, destructiveHint: true, idempotentHint: false, openWorldHint: true };

export function truncate(text: string, maxChars: number): string {
  if (text.length <= maxChars) return text;
  return `${text.slice(0, maxChars)}\n… [output truncated for the model: ${text.length - maxChars} more characters. Narrow the request (fields, maxResults, filters).]`;
}

export function jsonResult(data: unknown, maxChars: number): CallToolResult {
  const text =
    data === null || data === undefined ? 'OK (no content)' : typeof data === 'string' ? data : JSON.stringify(data);
  return { content: [{ type: 'text', text: truncate(text, maxChars) }] };
}

export function errorResult(error: unknown): CallToolResult {
  const message = error instanceof Error ? error.message : String(error);
  return { isError: true, content: [{ type: 'text', text: message }] };
}

export function defineTool<S extends z.ZodObject>(
  server: McpServer,
  deps: ToolDeps,
  name: string,
  config: { title: string; description: string; inputSchema: S; annotations: ToolAnnotations },
  handler: (args: z.output<S>) => Promise<unknown>,
): void {
  server.registerTool(name, config, async (args: z.output<S>, ctx: ServerContext) => {
    try {
      // Cancelling the MCP call aborts the Jira request(s) made by the handler (see JiraClient).
      const data = await runWithCancellation(ctx.mcpReq.signal, () => handler(args));
      return jsonResult(data, deps.maxOutputChars);
    } catch (error) {
      return errorResult(error);
    }
  });
}
```

```ts
import { Client } from '@modelcontextprotocol/client';
import { InMemoryTransport, McpServer, type ToolAnnotations } from '@modelcontextprotocol/server';
import { vi } from 'vitest';
import { JiraClient, type FetchLike } from '../http/jira-client.ts';
import type { ToolDeps } from '../tools/shared.ts';

export interface HarnessOptions {
  /** Defaults to false, like production. */
  allowWrites?: boolean;
  maxOutputChars?: number;
  maxResponseBytes?: number;
}

export interface RecordedRequest {
  method: string;
  url: URL;
  headers: Record<string, string>;
  /** Parsed JSON for string bodies, the raw value otherwise (e.g. FormData). */
  body: unknown;
}

export interface ListedTool {
  name: string;
  description?: string;
  annotations?: ToolAnnotations;
}

export interface Harness {
  fetchMock: ReturnType<typeof vi.fn<FetchLike>>;
  call(
    name: string,
    args?: Record<string, unknown>,
    options?: { signal?: AbortSignal },
  ): Promise<{ isError: boolean; text: string }>;
  request(index?: number): RecordedRequest;
  listTools(): Promise<ListedTool[]>;
  listToolNames(): Promise<string[]>;
  close(): Promise<void>;
}

export function jsonResponse(body: unknown, status = 200): Response {
  return new Response(JSON.stringify(body), {
    status,
    headers: { 'content-type': 'application/json;charset=UTF-8' },
  });
}

export function noContent(): Response {
  return new Response(null, { status: 204 });
}

export async function createHarness(
  build: (deps: ToolDeps) => McpServer,
  options: HarnessOptions = {},
): Promise<Harness> {
  const fetchMock = vi.fn<FetchLike>();
  const client = new JiraClient({
    baseUrl: 'https://jira.test',
    pat: 'test-pat',
    allowWrites: options.allowWrites ?? false,
    timeoutMs: 1000,
    maxResponseBytes: options.maxResponseBytes ?? 1024 * 1024,
    fetch: fetchMock,
    sleep: async () => {},
  });
  const server = build({ client, maxOutputChars: options.maxOutputChars ?? 100_000 });
  const [clientTransport, serverTransport] = InMemoryTransport.createLinkedPair();
  await server.connect(serverTransport);
  const mcp = new Client({ name: 'test-client', version: '0.0.0' });
  await mcp.connect(clientTransport);

  const listTools = async (): Promise<ListedTool[]> => {
    const { tools } = await mcp.listTools();
    return tools.map((t) => ({ name: t.name, description: t.description, annotations: t.annotations }));
  };

  return {
    fetchMock,
    async call(name, args = {}, options = {}) {
      try {
        const result = await mcp.callTool({ name, arguments: args }, { signal: options.signal });
        const first = result.content[0];
        return { isError: result.isError === true, text: first?.type === 'text' ? first.text : '' };
      } catch (error) {
        // Unknown tools and input validation failures may surface as protocol errors.
        return { isError: true, text: error instanceof Error ? error.message : String(error) };
      }
    },
    request(index = 0) {
      const call = fetchMock.mock.calls[index];
      if (!call) throw new Error(`fetch call #${index} not found (${fetchMock.mock.calls.length} calls)`);
      const [input, init = {}] = call;
      const raw = init.body;
      return {
        method: init.method ?? 'GET',
        url: new URL(String(input)),
        headers: (init.headers ?? {}) as Record<string, string>,
        body: typeof raw === 'string' ? (JSON.parse(raw) as unknown) : raw,
      };
    },
    listTools,
    async listToolNames() {
      return (await listTools()).map((t) => t.name).sort();
    },
    async close() {
      await mcp.close();
      await server.close();
    },
  };
}

export function createToolHarness(
  register: (server: McpServer, deps: ToolDeps) => void,
  options: HarnessOptions = {},
): Promise<Harness> {
  return createHarness((deps) => {
    const server = new McpServer({ name: 'test-server', version: '0.0.0' });
    register(server, deps);
    return server;
  }, options);
}
```

```ts
import { z } from 'zod';

const scalar = z.union([z.string(), z.number(), z.boolean()]);
const callInput = z.object({
  operationId: z.string().min(1).describe('e.g. "GET /rest/api/2/issue/{issueIdOrKey}"'),
  pathParams: z.record(z.string(), z.union([z.string(), z.number()])).optional(),

export function registerGenericTools(server: McpServer, deps: ToolDeps, catalog: Catalog): void {
  const { client } = deps;
  const source = catalog.meta
    ? `Jira ${catalog.meta.jiraVersion} WADL fetched ${catalog.meta.fetchedAt}`
    : 'instance WADL';

  defineTool(
    server,
    deps,
    'jira_list_operations',
    {
      title: 'List Jira REST operations',
      description: `Search the ${catalog.size} operations described by the ${source} for REST API v2, Agile 1.0 and Xray (other REST families are not covered). All terms must match the operation id ("METHOD /path") or its summary. Each operation has an access class (read, write, destructive); "not individually reviewed" in its reason means the class comes from the HTTP method only.`,
      inputSchema: z.object({
        query: z.string().optional().describe('Keywords, e.g. "worklog", "sprint issue", "version"'),
        api: z.enum(['api', 'agile', 'xray']).optional().describe('api = REST v2, agile = boards/sprints, xray = tests'),
        method: z.enum(['GET', 'POST', 'PUT', 'DELETE']).optional(),
        access: z.enum(['read', 'write', 'destructive']).optional(),
        limit: z.number().int().min(1).max(100).default(20),
      }),
      annotations: READ,
    },
    async ({ query, api, method, access, limit }) => {
      const { total, operations } = catalog.search({ query, api, method, access, limit });
      return {
        total,
        returned: operations.length,
        operations: operations.map((op) => ({ operationId: op.id, access: op.access, summary: op.summary })),
      };
    },
  );

  defineTool(
    server,
    deps,
    'jira_describe_operation',
    {
      title: 'Describe a Jira REST operation',
      description:
        'Full definition of an operation: access class and its origin, path/query parameters (type, required when declared, repeatable), accepted body media types, and what the server does and does not validate.',
      inputSchema: z.object({ operationId: z.string().min(1) }),
      annotations: READ,
    },
    async ({ operationId }) => describeOperation(catalog.require(operationId)),
  );

  defineTool(
    server,
    deps,
    'jira_call_read_operation',
    {
      title: 'Call a read operation',
      description:
        'Call a catalog operation classified "read" (includes POST operations reviewed as read, such as JQL search). Use jira_list_operations then jira_describe_operation first.',
      inputSchema: callInput,
      annotations: READ,
    },
    async ({ operationId, pathParams, query, body }) => {
      const op = catalog.require(operationId);
      if (op.access !== 'read') {
        throw new CatalogError(
          `${op.id} is classified "${op.access}" (${op.accessReason}). Use jira_call_write_operation${
            client.allowWrites ? '' : ', available only when the server runs with JIRA_ALLOW_WRITES=true'
          }.`,
        );
      }
      return (await client.request(catalog.buildRequest(op, { pathParams, query, body }))).data;
    },
  );

  if (!client.allowWrites) return;

  // H13 — conservative annotation: this single tool may call deletions, and an operation
  // classified "write" may turn out to be destructive if the review missed it. Annotations are
  // only hints for MCP clients; the server enforces the write policy itself.
  defineTool(
    server,
    deps,
    'jira_call_write_operation',
    {
```

````markdown
# jira-mcp

Serveur MCP (stdio) générique pour **Jira Software Server / Data Center 8.x** (REST API v2).

> Les valeurs d'exemple de ce document sont **fictives** : `https://jira.example.com`, projet `DEMO`, utilisateur `jdoe`, secret `JIRA_READONLY_PAT`. Remplacez-les par les vôtres, sans jamais les versionner si elles sont sensibles.

## Portée

- Environ 25 outils dédiés : recherche JQL, tickets, transitions, commentaires, worklogs, liens, pièces jointes, tableaux et sprints.
- Les opérations **décrites dans les WADL de votre instance** pour **REST API v2**, **Agile 1.0** et **Xray** (si installé), via `jira_list_operations` → `jira_describe_operation` → `jira_call_read_operation` / `jira_call_write_operation`.

**Non couvert :**
- Jira Service Management ;
- les API REST des autres plugins ;
- les API annexes de Jira (`/rest/greenhopper`, `/rest/auth`, `/rest/pat`, `/rest/dev-status`, `/rest/plugins`, `/rest/applinks`).

**Limites des WADL :**
- pas de schéma de corps, et rien qui dise si un corps est requis ;
- paramètres requis rarement déclarés ;
- **aucune information sur les effets de bord** ;
- inventaire figé à la date du téléchargement.

## Prérequis

- **Node.js** 24.11 ou plus récent.
- **Réseau.** La machine qui exécute le serveur doit joindre l'instance Jira en HTTPS.
- **PAT.** Créez-le avec un compte dont les **permissions Jira sont minimales** pour l'usage visé : en lecture, un compte sans droit d'écriture.
- **Autorité de certification privée.** Si l'instance utilise une autorité privée, rendez-la visible de Node, de l'une de ces deux façons :
  - installez-la dans le magasin de certificats du système, puis lancez Node avec `--use-system-ca` (les scripts npm le font déjà) ;
  - ou définissez `NODE_EXTRA_CA_CERTS=<chemin du fichier PEM>`.

  Ne désactivez jamais la vérification TLS.

## Sécurité

- **Lecture seule par défaut.** `JIRA_ALLOW_WRITES=true` active les outils d'écriture (dont `jira_add_attachment`) et `jira_call_write_operation`.
- **Classe d'accès.** Chaque opération du catalogue a une classe : `read`, `write` ou `destructive`.
  - Elle vient d'une règle par défaut, selon la méthode HTTP, ou d'une **décision de revue signée**, consignée dans `catalog/access-decisions.json`.
  - Des heuristiques de chemin désignent les opérations à revoir : GET dont le nom évoque un effet de bord, POST dont le nom évoque une lecture, POST/PUT/PATCH dont le nom évoque une suppression.
  - **Ces heuristiques ne détectent rien** : chaque candidat est décidé par une personne, et `npm run catalog:check` bloque tant qu'un candidat n'est pas décidé.
- **Risque résiduel sur les GET.**
  - Les GET qui ne sont pas des candidats restent `read` sans revue individuelle ; leur `accessReason` le signale (`not individually reviewed`).
  - Un GET à effet de bord dont le nom paraît anodin ne serait donc pas signalé.
  - Ce risque est accepté explicitement à chaque livraison, dans une note de `docs/delivery/`.
  - **La barrière effective reste les permissions Jira du PAT utilisé.**
- **Annotations MCP.** Ce sont des **indications** pour le client MCP, par exemple pour qu'il demande une confirmation ; elles ne protègent rien.
  - Les outils dédiés ont des annotations précises.
  - `jira_call_write_operation` est annoté `destructiveHint: true` **par choix conservateur**, même pour une modification courante, car il peut aussi appeler des suppressions.
- **Reprises.** Seules les lectures sont réessayées : sur 429, 502, 503, 504 ou erreur réseau, avec 2 reprises au maximum. Une écriture n'est jamais rejouée.
- **Annulation.** Si le client MCP annule un appel, la requête Jira en cours est interrompue et n'est pas réessayée. Une écriture déjà reçue par Jira a pu être appliquée : vérifiez son état avant de la relancer.
- **Transport.**
  - **HTTPS est exigé par défaut.**
  - Une URL `http://` n'est acceptée qu'avec `JIRA_ALLOW_INSECURE_HTTP=true`, pour des tests locaux exceptionnels. Le serveur affiche alors un avertissement au démarrage, car le PAT circule en clair.
  - Les redirections sont refusées.
- **Taille.**
  - Au-delà de `JIRA_MAX_RESPONSE_BYTES`, la lecture est interrompue et une erreur est renvoyée.
  - La sortie destinée au modèle est limitée à `JIRA_MAX_OUTPUT_CHARS`, avec la mention « output truncated ».
- **Secrets et inventaire.**
  - Le PAT n'est jamais journalisé ni versionné (`npm run secrets:scan`).
  - L'URL de l'instance n'est pas journalisée au démarrage.
  - L'inventaire des endpoints (WADL, `catalog/catalog.json`, rapports) **n'est pas versionné**.
````

```ts
const ALLOWED: readonly RegExp[] = [
  /^package\/package\.json$/,
  /^package\/README\.md$/,
  /^package\/LICENSE(\.\w+)?$/,
  /^package\/dist\/.+\.(js|js\.map|d\.ts)$/,
  /^package\/catalog\/catalog\.json$/,
];

/** Entries of an `npm pack` tarball that should not be shipped. */
export function unexpectedEntries(entries: readonly string[]): string[] {
  return entries.filter((entry) => !ALLOWED.some((pattern) => pattern.test(entry)));
}

/** Values that must never appear in the package: the PAT and the instance host. */
export function sensitiveLiterals(env: Readonly<Record<string, string | undefined>>): string[] {
  const values: string[] = [];
  if (env.JIRA_PAT) values.push(env.JIRA_PAT);
  if (env.JIRA_BASE_URL && URL.canParse(env.JIRA_BASE_URL)) values.push(new URL(env.JIRA_BASE_URL).host);
  return values;
}
```

```ts
  console.error('usage: node scripts/check-package.ts <package.tgz>');
  process.exit(1);
}
const entries = execFileSync('tar', ['-tzf', tarball], { encoding: 'utf8' }).split('\n').filter(Boolean);
const problems = unexpectedEntries(entries).map((entry) => `unexpected file: ${entry}`);

const dir = await mkdtemp(join(tmpdir(), 'jira-mcp-pack-'));
try {
  execFileSync('tar', ['-xzf', tarball, '-C', dir]);
  const literals = sensitiveLiterals(process.env);
  for (const entry of entries) {
    const text = await readFile(join(dir, entry), 'utf8').catch(() => '');
    // Only names of findings are printed, never the matched values.
    const hits = findSecrets(text);
    if (literals.some((value) => text.includes(value))) hits.push('sensitive environment value');
    if (hits.length > 0) problems.push(`${entry}: ${hits.join(', ')}`);
  }
} finally {
  await rm(dir, { recursive: true, force: true });
}

if (problems.length > 0) {
  for (const p of problems) console.error(`✖ ${p}`);
  process.exit(1);
}
console.error(`✔ package content checked (${entries.length} files)`);
```

```yaml
# Generic CI: no organisation, instance URL or credential is hard-coded.
# Repository settings (all names are examples): secrets JIRA_READONLY_PAT and JIRA_BASE_URL
# (a secret, so that GitHub masks the instance URL in logs; repository variables are not masked);
# variables JIRA_CI_ENABLED ('true' to run the Jira job), SMOKE_PROJECT, JIRA_RUNNER_LABEL, PUBLISH_ARTIFACT.
name: ci

on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  static:
    # No secret, no Jira access, no generated catalog needed.
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
        with:
          persist-credentials: false
      - uses: actions/setup-node@v4
        with:
          node-version: '24.11'
          cache: npm
      - run: npm ci
      - run: npm run check

  catalog-and-package:
    needs: static
    # Skipped unless enabled (a job-level if cannot read secrets), and for pull requests from forks (secrets are not available there).
    if: >-
      vars.JIRA_CI_ENABLED == 'true' &&
      (github.event_name != 'pull_request' || github.event.pull_request.head.repo.full_name == github.repository)
    # GitHub-hosted only if the instance is reachable from the Internet with a public CA;
    # otherwise a self-hosted runner inside a network that reaches it and trusts its CA.
    runs-on: ${{ vars.JIRA_RUNNER_LABEL || 'ubuntu-latest' }}
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4
        with:
          persist-credentials: false
      - uses: actions/setup-node@v4
        with:
          node-version: '24.11'
          cache: npm
      - run: npm ci

      # The PAT and the instance URL (both secrets) are passed only to the steps that call Jira or look for their value.
      - name: Fetch WADL (read-only PAT)
        env:
          JIRA_BASE_URL: ${{ secrets.JIRA_BASE_URL }}
          JIRA_PAT: ${{ secrets.JIRA_READONLY_PAT }}
        run: npm run catalog:fetch

      - name: Build and check the catalog
        run: npm run catalog:build && npm run catalog:check

      - name: Build
        run: npm run build

      - name: Smoke test (read-only)
        env:
          JIRA_BASE_URL: ${{ secrets.JIRA_BASE_URL }}
          JIRA_PAT: ${{ secrets.JIRA_READONLY_PAT }}
          SMOKE_PROJECT: ${{ vars.SMOKE_PROJECT }}
        run: npm run smoke

      - name: Pack
        run: npm pack

      - name: Check the package (expected files, no PAT, no instance host)
        env:
          JIRA_BASE_URL: ${{ secrets.JIRA_BASE_URL }}
          JIRA_PAT: ${{ secrets.JIRA_READONLY_PAT }}
        run: node scripts/check-package.ts jira-mcp-*.tgz

      # Anyone with read access to the repository can download artifacts: private or internal repositories only.
      - name: Keep the package
        if: vars.PUBLISH_ARTIFACT == 'true'
        uses: actions/upload-artifact@v4
        with:
          name: jira-mcp-package
          path: jira-mcp-*.tgz
          retention-days: 14
          if-no-files-found: error

      # Matters on self-hosted runners, whose workspace persists between jobs.
      - name: Remove the endpoint inventory from the workspace
        if: always()
        run: rm -rf catalog/wadl catalog/catalog.json catalog/last-diff.md catalog/review.md dist jira-mcp-*.tgz
```

**Ce que fait ce workflow :**
- Le job `catalog-and-package` échoue tant que l'instance ne correspond plus au verrou, ou qu'un candidat attend sa revue. C'est voulu : la CI ne met jamais le verrou à jour d'elle-même.
- Toutes les étapes impriment des comptes ou des versions, jamais l'URL ni la liste des endpoints (`CI=true` est défini par GitHub Actions). GitHub masque en outre la valeur des secrets dans les journaux.
- Le PAT et l'URL de l'instance sont des secrets, exposés seulement aux trois étapes qui en ont besoin ; ce ne sont pas des variables d'environnement du job. L'URL n'est pas une variable de dépôt, car GitHub affiche l'environnement de chaque étape dans le journal sans masquer les variables.
- Le job Jira est activé par la variable non sensible `JIRA_CI_ENABLED`, car une condition `if` de job ne peut pas lire un secret.
